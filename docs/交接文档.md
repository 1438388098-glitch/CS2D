## 1. 系统架构速览

```
游戏（浏览器端）                         训练（Node.js headless）
┌─────────────────────┐                ┌──────────────────────────────┐
│ src/ai/decisions.js │◄──netWeights───│ scripts/train-dqn.mjs (主进程) │
│   netAct(): 推理入口  │   config.js    │   ├─ 8× worker_threads        │
│   netObsTeam(): 33维 │   ladder[12]   │   │   (train-dqn-worker.mjs)   │
│   netObjective(): 执行│                │   ├─ 对手池 pool/ (快评淘汰)   │
│ src/dqn.js: MLP 推理  │                │   └─ 96回合双对手终评          │
└─────────────────────┘                │ scripts/prepare-imitation.mjs │
                                       │   (模仿预训练 → warm start)    │
                                       └──────────────────────────────┘
```

**决策链路**：`botObjectiveRaw()` → `netAct(e, game)`（33 维观测 → argmax）→ `netObjective()`（动作+路线 → 具体目标点）→ 规则层寻路/执行。

**网络结构**：MLP 33→32→18（H12 现役）/ 33→32→36（节奏版代码保留）。纯 JS 零依赖，JSON 权重内嵌 config.js。

## 2. 快速上手（三命令）

```bash
# 1. 模仿预训练（约 2 分钟，产出 net-imitation-pretrain.json）
node scripts/prepare-imitation.mjs 90

# 2. 训练（8 worker × 12 万步，约 15-25 分钟，产出 net-weights-trained.json）
node scripts/train-dqn.mjs 120000 8

# 3. 部署到 H12：把 net-weights-trained.json 的 weights 内嵌进 src/config.js ladder[12]
#    （用 gen-ladder12 脚本生成行，替换 ladder[12] 整行）
```

**后台运行 + 实时日志**（避免输出丢失）：
```powershell
$p = Start-Process node -ArgumentList 'scripts/train-dqn.mjs','120000','8' `
  -WorkingDirectory 'D:\Claudeworkspace\CS2D' `
  -RedirectStandardOutput 'train-run.log' -RedirectStandardError 'train-err.log' -PassThru
# 查看进度：Get-Content train-run.log -Tail 10
```

## 4. 已知坑（踩过，勿重踩）

1. **评估种子敏感**：单 seedOffset 96 回合波动 ±10pp。关键对比用 3 个 seedOffset（900/913/926）平均。
2. **过拟合模式**：固定规则对手下 10 万步是峰值，20 万步必退化。终评必须包含 pool/ 目录 checkpoint（10 万步 checkpoint 常强于终态）。
3. **训练胜率 ≠ 真实水平**：训练胜率 35-40% 正常（ε 探索 × 5 bot 团队代价），真实能力看评估（argmax）。
4. **20s 回合会压垮战术**：T 分路→进点→安弹周期需要 35s，回合时长不可低于 ~30s。
5. **动作空间膨胀要配训练量**：36 动作需要 >40 万步才有可比性（当前 12 万步不够）。
6. **BUY 阶段禁网络决策**：netAct 有 `game.state !== 'LIVE'` 守卫，删了会导致 IGL 回合初 rotate → 全队角色展平（历史 bug）。
7. **PowerShell 转义坑**：含 `\u` 或中文字符串的 node -e 会炸；用临时 .mjs 文件替代。
8. **输出丢失坑**：`Select-Object -Last` 缓冲全部输出直到进程结束；长任务用 Start-Process + 日志文件。
9. **config.js 编码**：改写必须用 `[System.IO.File]::WriteAllText(..., UTF8Encoding($false))`，Set-Content 会加 BOM 破坏加载。
10. **对手池性价比低**：自对弈在当前训练量下无增益，反而引入非平稳；如重试需"延迟建池（>6 万步）+ 低比例（≤30%）"。

## 5. 下一步建议（按优先级）

1. **回归验证 49% 权重**：用多 seedOffset 确认 H12 现役权重的真实水平（若 45-52% 区间内即维持现状）。
2. **训练量规模化**：唯一被证明能提升的方向——10 万步是峰值意味着欠拟合；上 40 万步 × 16 worker（过夜）配合池最佳选择，预期破 52%。
3. **多图迁移**：观测已地图归一化（含 W/H 维），dust2 达标后直接 canal/metro 微调，每图独立评估。
4. **蒸馏**：冠军权重蒸馏 33×24×18 小网络（部署体积减半）。
5. **共享回放（A3C 风格）**：样本效率是当前最大短板，worker 独立回放浪费严重。
