## 1. 项目概览

CS2D 是 HTML5 Canvas 平面 5v5 战术射击游戏（CS 规则简化版）。v3.0 在 v2 基础上完成四大能力建设：

| 编号 | 能力 | 需求来源 | 状态 |
|---|---|---|---|
| A | 弹道系统：不同枪械扩散曲线 × 移动速度 | 用户需求 1 | 见 §3 |
| B | 渲染精细化：光照/纹理/粒子/特效 | 用户需求 2 | 见 §4 |
| C | 多地图：5 张可玩地图 + 地图选择 | 用户需求 3 | 见 §5 |
| D | 地狱人机：进化学习训练的顶级 AI + 训练框架 | 用户需求 4 | 见 §6 |

前置：v2 已完成的审查修复（5 个并行 agent 输出 60+ 问题，P0/P1 已修复并回归）。

## 3. 弹道系统设计（需求 A）

### 3.1 目标

- 每把枪有独特的扩散曲线（首发准、连发扩散、恢复速度）
- 移动速度影响扩散：站立 < 静步 < 奔跑 < 蹲伏（最优）
- 与后坐力/准星联动：准星开口实时反映当前散布

### 3.2 扩散模型

每把武器新增 `ballistic` 配置（config.js WEAPONS）：

```js
ballistic: {
  first: 0.45,     // 首发精度系数（乘基础散布，越小越准）
  perShot: 0.18,   // 每发扩散增量（连发扩散斜率）
  max: 3.0,        // 最大扩散倍数
  recover: 1.8,    // 停火恢复速率（秒）
  move: {          // 移动扩散系数
    stand: 1.0,    // 站立
    walk: 0.55,    // 静步（Shift）
    run: 2.2,      // 奔跑
    crouch: 0.75   // 蹲伏
  }
}
```

### 3.3 计算流程（ballistic.js）

```
effectiveSpread = baseSpread
  × firstMultiplier(shotStreak==0 ? first : 1)
  × shotStreakMultiplier(1 + perShot×min(shotStreak, max-1))
  × moveMultiplier(按移动速度档)
  × crouchMultiplier(蹲伏 0.85)
  × botDifficulty(spreadMult，仅 bot)
```

- `shotStreak`：连续射击计数，停火 >500ms 或换弹/切枪清零（entities.js 已有字段）
- 后坐力 `recoil` 独立叠加到准星开口，与扩散解耦
- 半自动武器（auto:false）：点击边沿触发（game.js 已实现），连发扩散不适用

### 3.4 武器参数表（草案，实现时调参）

| 武器 | first | perShot | max | recover | 移动敏感度 |
|---|---|---|---|---|---|
| AK-47 | 0.40 | 0.22 | 3.0 | 1.6 | 高 |
| M4A4 | 0.45 | 0.18 | 2.6 | 1.8 | 中 |
| AWP | 0.30 | — | 1.2 | 2.5 | 极高（移动惩罚） |
| 冲锋枪 | 0.60 | 0.15 | 3.5 | 2.0 | 低（跑打） |
| 手枪 | 0.50 | 0.25 | 2.0 | 1.5 | 中 |
| 霰弹 | 0.80 | 0.10 | 1.5 | 2.2 | 低 |
| 机枪* | 0.55 | 0.20 | 3.2 | 1.4 | 极高 |

\* 机枪为规划武器（v3.1 可选）

### 3.5 准星联动

- 准星 gap = 基础 6 + recoil×14 + spread×10（hud.js renderCrosshair 参数化）
- 命中/脱靶反馈：命中红色 X，脱靶白色 X（已有 hitMarkT）

## 4. 渲染精细化设计（需求 B）

### 4.1 光照系统（顶视图）

- **静态光照烘焙**（textures.js）：每个地砖烘焙环境光 + 遮挡阴影：
  - 墙体边缘生成软阴影（沿墙方向渐变暗带，模拟低角度光照）
  - 站点区域暖色/冷色调（A 暖橙、B 冷蓝）
  - 随机砖缝/污渍/杂物纹理（噪声层）
- **动态光照**：
  - 爆炸/枪口闪光在粒子层叠加径向光晕（composite 'lighter'）
  - 炸弹安装后区域脉动红光（已有，增强为光晕扩散）

### 4.2 纹理分级

| 层级 | 内容 | 更新频率 |
|---|---|---|
| L0 静态层 | 地板/墙体/箱子/站点标记 | 回合开始 |
| L1 装饰层 | 弹孔/尸体/血渍（增量化绘制） | 事件触发 |
| L2 动态层 | 实体/粒子/曳光/烟雾 | 每帧 |
| L3 全屏层 | 闪光/低血/伤害指示 | 每帧 |

### 4.3 粒子增强

- 弹道粒子：弹着点火花 + 二次弹跳碎屑
- 血液：动态扩散（径向渐变，随生命衰减扩大）
- 烟雾：双层渐变（外浓内淡）+ 边缘卷曲（sin 扰动）
- 爆炸：冲击波环 + 地面闪光扇形 + 上升火星
- 曳光：拖尾渐变（起点透明 → 终点亮）

### 4.4 实体渲染

- 队伍光环（v2 已加）：脚下 16px 队伍色圆环
- 行走摆动：身体 bob 幅度随速度
- 枪口火光：分层（亮心 + 外焰）
- 蹲伏姿态：实体缩小 + 阴影压扁

## 5. 多地图系统设计（需求 C）

### 5.1 数据化地图

`config.js` 新增 `MAPS` 数组，每张地图独立数据：

```js
{
  id: 'dust2',
  name: '沙漠峡谷',
  rows: [[count,ch],...],     // 网格（复用现有 ROWS 结构）
  sites: { A: {...}, B: {...} },  // 站点矩形
  cthold: { A: [...], B: [...] }, // CT 守点锚点（含朝向）
  accent: '#ff8a2a'           // 地图主题色
}
```

`map.js` 改为实例化：`createMap(mapDef)` → 返回 {grid, walkable, passable, los, aStar, spawns, sites, holds}。`game.currentMap` 持有当前实例，所有模块通过 `game.map` 访问（消除 SITES/SPAWN 全局依赖）。

### 5.2 五张地图

| id | 名称 | 特征 | 尺寸 |
|---|---|---|---|
| dust2 | 沙漠峡谷 | 经典三通道 + 中门（现有图） | 60×45 |
| snow | 冰雪基地 | 对称镜像、开阔中庭、A/B 点对称 | 60×45 |
| depot | 仓库禁区 | 室内紧凑、密集箱区、短枪线 | 56×44 |
| canal | 运河小镇 | 双层通道、长枪线、水渠遮挡 | 64×46 |
| metro | 地铁枢纽 | 三线狭长、多拐角、CQB 图 | 58×42 |

每张图要求：
- A/B 双爆破点 + T/CT 出生区（'a'/'b'/'t'/'c' 字符标记）
- 全图 BFS 连通性自检通过（map.js 已有，加载时报不可达格）
- CT 守点锚点 ≥4 个/点（面向入口）
- 地图尺寸变化时：相机边界 clamp（v2 已实现，读 mapW/mapH）

### 5.3 地图选择 UI

主菜单新增"选择地图"行：5 张地图卡片（名称 + 主题色块），localStorage 记忆上次选择。选图在 `startMatch` 时加载 `game.currentMap`。

### 5.4 兼容策略

- 战斗/渲染/HUD 全部改为 `game.map.sites` / `game.map.spawns` 引用
- 站点标记/纹理按当前图重烘焙（initTextures(game.map)）
- AI 锚点从 `game.map.holds` 读取（config 的 CT_HOLD 迁移到各图定义）

## 6. 地狱人机 + 训练框架设计（需求 D）

### 6.1 原则

- **不靠外挂**：不开透视、不改伤害、不锁头。地狱 AI 与普通 bot 共用同一套感知/决策代码，仅**参数不同**。
- **学习驱动**：用进化策略（Evolution Strategy）在无头模拟中优化 bot 决策参数，从"最优参数"中提炼地狱难度。
- **可复现**：确定性 RNG（seedable），训练/回放/测试共用。

### 6.2 基因定义（ai-genome.js）

10 维基因，每维范围 [0,1]，映射到 AI 参数：

| 基因 | 映射 | 含义 |
|---|---|---|
| g0 | react = 0.05 + g0×0.5 | 反应时间（越小越快） |
| g1 | spreadMult = 0.5 + g1×1.5 | 命中精度（越小越准） |
| g2 | view = 800 + g2×500 | 视野半径 |
| g3 | aimSpeed = 60 + g3×120 | 转身速度 |
| g4 | strafe = 0.2 + g4×0.6 | 走位频率（越小越沉稳） |
| g5 | idealMin = 200 + g5×400 | 交火距离带下限 |
| g6 | idealMax = 550 + g6×400 | 交火距离带上限 |
| g7 | peekChance = g7×0.5 | 探头时机把握 |
| g8 | nadeUse = 0.2 + g8×0.8 | 道具使用倾向 |
| g9 | riskT = 0.3 + g9×1.2 | 拆弹/装弹风险容忍 |

地狱难度 = 训练出的精英基因映射（写入 config DIFF.hell）。

### 6.3 训练框架（train/）

```
train/evolve.js
  1. 初始化种群（POP=32，随机基因）
  2. 每代（GEN=50）：
     a. 评估：每个基因个体作为"地狱队"（5 bot）
        对抗"基线队"（5 个普通难度 bot），打 N=24 局
        fitness = 击杀差×2 + 装弹成功×3 + 胜局×5（归一化）
     b. 选择：锦标赛（k=3）取前 50%
     c. 交叉：均匀交叉生成子代
     d. 变异：10% 概率高斯扰动 σ=0.15
     e. checkpoint：每 10 代保存精英基因（JSON）
  3. 收敛后输出 best-genome.json → config DIFF.hell
```

- **加速手段**：无头模拟（test/simulate 基础）+ 缩短购买期（0.8s）+ 强制 6s 结算 + 只模拟关键帧（update 固定 30Hz）
- **单个个体评估耗时**：约 24 局 × 0.5s ≈ 12s → 每代 32×12s ≈ 6.4 分钟 → 50 代 ≈ 5.3 小时（可断点续训）

### 6.4 训练计划（1 亿次）

"1 亿次"按决策评估量定义：**1 亿次 bot 决策评估 ≈ 4 千万帧 ≈ 44 万局对战**。

| 阶段 | 目标 | 规模 | 说明 |
|---|---|---|---|
| S1 可行性 | 验证框架收敛 | 100 代 × 32 个体 × 24 局（≈1.2 万局） | 约 10 小时，产出 v1 地狱参数 |
| S2 强化 | 5 张地图泛化 | 每图 300 代（≈11 万局） | 约 3 天/图，产出 per-map 参数 |
| S3 大规模 | 1 亿次决策评估 | 44 万局（≈1.1 亿决策） | 分布式/断点续训，产出最终参数 |
| S4 验证 | 地狱 vs 困难对局 1000 局 | 胜率统计 + 人类局内表现 | 达标：≥65% 胜率 |

交付物：训练框架（可运行）+ S1 实际训练产出 v1 地狱参数 + 训练日志/README。

### 6.5 地狱难度特性（参数之外）

- 预瞄：转向平滑 + 预判目标移动（lead 补偿增强）
- 压枪：连发时自动下压（基于弹道参数）
- 补枪：队友阵亡后 0.8s 内转移到击杀者位置压制
- 全部不违反"不靠外挂"：以上均为参数/策略，不读玩家额外信息

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
