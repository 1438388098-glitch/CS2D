## 2. Godot 移植架构

### 2.1 状态三层分离
| 状态 | JS | Godot |
|---|---|---|
| 个体经济 | e.money/e.lossStreak/e.weapons/e.armor/e.helmet/e.ammoMap/e.reserveMap | **Player 节点属性** |
| 团队连败 | game.lossStreakT/CT | **Match 节点** |
| 每回合购买规划 | game.teamBuyType/teamBuyPlan/ctKitRound/ctKitBought | **Match 临时 Dict** |

- `Economy.gd`(autoload) 持有静态常量 + `add_money/next_round_budget/clear_equipment/buy_item`。
- 与 `Weapons` autoload 解耦，价格查询走武器注册表。

### 2.2 购买 UI（Control 节点）
- `buy-head/buyCash` → HBoxContainer+Label；`buy-eco` → Label；`buy-cats` → VBoxContainer(7 Button)；`buy-grid` → GridContainer(物品卡=Button+HBox：图标+名称/描述+价格)。
- 三态呈现：owned→modulate+“✓ 已拥有”；locked→禁用+"仅 T/CT"；买不起→价格变灰。
- 刷新：Economy 成功时 `signal money_changed/inventory_changed`；Match `signal buy_updated/team_buy_planned/round_settled`。
- 输入：InputMap action buy/buy_cat_1..7；B/数字在 `_unhandled_input`。
- 购买窗口：可购窗口做成 Match 状态机查询函数（**不绑死 state==BUY**）。

### 2.3 AI 购买决策平移
- 架构 1:1 平移；`rand()` → 注入 RandomNumberGenerator（set_seed）。
- 重构点：opts 闭包→命名字段；drops 生成器；`applyTeamBuyToPlan` 闭环→signal；hasGoodGun→WeaponUtil。

## 4. 难点与风险

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| 4.1 | HUD/计分板/购买菜单三方联动 | 高 | 统一信号拓扑：Economy.money_changed / Match.buy_updated |
