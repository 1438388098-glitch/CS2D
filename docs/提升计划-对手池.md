# 下一步提升计划：对手池自对弈（阶段 3）

> 基于 1 小时快速迭代的实证结论：per-bot 奖励（loss 50→8）+ 33 维观测让胜率从 33% 基线冲到峰值 52%，但**固定规则对手导致 20 万步过拟合**（exploit 规则 CT 盲区，评估退到 48%）。下一步核心 = 打破固定对手，让网络学到泛化能力。

---

## 一、目标（可量化验收）

| 指标 | 当前 | 目标 | 验证方式 |
|---|---|---|---|
| 对规则 CT 胜率 | 48-52% | **≥55%** | 96 回合评估（三经济场景各 32 回合） |
| 对历史自对弈对手 | 未测 | **≥48%** | 同上，对手从 checkpoint 池采样 |
| 20 万步后不退步 | 48%（过拟合） | **保持 ≥52%** | 每 5 万步 checkpoint 复评 |
| 分路度 | 1.2-1.4 | **≥1.5** | 评估期全场帧统计 |
| 安弹率 | ≈0 | **≥15%** | 评估期统计 |

## 二、改动清单（按依赖顺序）

### 1. 对手池（核心，train-dqn.mjs + worker）
- **主进程**：
  - 收集 worker 完成消息时，把权重连同步数存入 `pool/`（按 workerId+step 命名，如 `pool/champ-w3-100000.json`）
  - 每 5000 步对池中最新权重做一次 24 回合快评；若优于池内最差则保留，池容量 **3 个**（超容淘汰最差）
- **worker**：
  - CT 侧对抗源按 **回合级** 轮换：50% 回合用规则 AI（当前实现），50% 回合从 `pool/` 随机取一个 checkpoint 当 CT 网络（`e.aiParams.netWeights = {__default: poolWeight}`）
  - 池为空（前期）→ 100% 规则 AI，平滑过渡
  - CT 用池权重时也走 `netAct` 26+ 维解码（argmax，ε=0）
- **注意**：worker 进程启动时扫描 `pool/` 加载 checkpoint；主进程写完池文件后广播 `pool-updated` 消息，worker 每 200 回合重扫一次（避免频繁 IO）

### 2. 评估体系升级（train-dqn.mjs）
- `EVAL_ROUNDS` 48 → 96（三经济场景各 32 回合，按 r%3 已有）
- 评估对手 = 规则 CT（现状）**+ 池中最佳 checkpoint**，分别报告：
  - `对规则 X%` / `对历史冠军 Y%`
- 候选评估排序：先看对规则，再看对历史（防"只会打规则"的权重）

### 3. 奖励微调（worker，针对安弹流）
- 安弹后守包 dense：plant 完成后，存活 T bot 每秒 +0.2（进点协同已有，补守包段）
- 转点协同：IGL rotate 触发（`game.tSwitchedAt` 变化且新攻击点安弹）→ 全队 +20 一次
- 其余保持（per-bot 击杀/助攻/eco 纪律已验证有效）

### 4. 过拟合护栏
- 主进程每 5 万步对"当前最佳"做一次复评；若相对上次 -5pp 以上，告警输出并回滚到上次 checkpoint 继续训练（简单版 early-stop）
- ε 下限 0.08 保持；训练步数上限 25 万/轮

### 5. 多图迁移（后置，达标才做）
- 观测已地图归一化（33 维含 W/H）
- dust2 达标后：`train-dqn.mjs` 加 `MAPS = ['dust2','canal','metro']` 轮换，warm start 用 dust2 冠军权重，每图评估分开报

## 三、执行步骤（每步含验证点）

1. **池基础设施**：`pool/` 目录 + 主进程 checkpoint 收集/快评/淘汰逻辑
   - 验证：跑 2 worker × 2 万步小样本，确认池文件生成、快评输出、worker 能加载池权重
2. **worker 对抗源轮换**：CT 50% 规则 / 50% 池 checkpoint
   - 验证：日志打印每回合 CT 对抗源（`CT:rule` / `CT:pool-w3`），确认轮换生效
3. **评估升级**：96 回合 + 双对手报告
   - 验证：输出格式含 `对规则 / 对历史` 两列
4. **奖励微调**：守包 dense + 转点协同
   - 验证：训练胜率曲线 + 安弹率
5. **正式训练**：8 worker × 25 万步（约 30-40 分钟）
   - 验证：中途 5 万步复评不过拟合
6. **终验 + 部署**：96 回合 × 双对手；达标 → 更新 H12（或新增 H13）；平衡回归 + modes PASS + 行为探针

## 四、时间预算

| 步骤 | 耗时 |
|---|---|
| 1-4 实现 + 小样本验证 | 20 分钟 |
| 5 正式训练 | 40 分钟 |
| 6 终验 + 部署 | 15 分钟 |
| **合计** | **~75 分钟** |

## 五、风险与兜底

- **自对弈震荡**（权重互相 exploit）：对手轮换粒度调参（5000 步→10000 步）、池内权重只留"对规则 ≥48%"的
- **训练变慢**（评估+IO 开销）：快评只对池最新权重、24 回合封顶；IO 用 200 回合重扫节流
- **单 worker 权重漂移**：冠军广播（池最佳 → 所有 worker 每 1 万步 warm start）作为备选，若轮换方案无效再启用
- **时间超支**：砍步骤 4（奖励微调），先验证对手池单点效果
